Pause stops the watcher and restores the displays; Resume starts it again. Restore displays now sends DCS 0x29 to both panels immediately, without changing the mode. Export copies the log and the previous run to /sdcard/Download.

Behaviour

One shared inactivity delay, in seconds (15-600; default 90). At most one mode can be on: turning Display off on turns Auto sleep off, and both off means the module does nothing on eye loss. Display off REPLACES sleep, so set the delay no lower than you would want the system to sleep -- the same delay applies to whichever mode is on.

Advanced

Reference and troubleshooting only. The defaults are safe; leave the ESD guard off unless you are holding the panels blank for a very long time.

Eye-signal source
logcat -s EyesMonitor:D CpmInput:I. Authoritative lines: EyesMonitor: eyeDetected : No eye detected and EyesMonitor: eyeDetected : Eyes detected!. Supplement: CpmInput: XREyeDevice - eyeState changed LEFT: n, RIGHT: n (present when either side is 1), used so the watcher still works if the EyesMonitor lines stop.
Blank / restore byte strings (DCS over debugfs)
Blank (0x28): 0x39 0x01 0x00 0x00 0x00 0x00 0x01 0x28
Restore (0x29): 0x39 0x01 0x00 0x00 0x00 0x00 0x01 0x29
Left: /sys/kernel/debug/dri/0/DSI-1/tx_cmd, right: /sys/kernel/debug/dri/1/DSI-2/tx_cmd.
Transfers work only while the display is On (dpms=On); success is confirmed by reading back last_cmd_tx_sts:0x1.
Off by default. When on, the watcher writes 0 to esd_check on both panels before blanking and restores it to 1 afterwards, so the ESD IRQ cannot silently unblank the panels during a long hold.
Config files
/data/adb/modules/gxr-display-off/mode, /delay, /esd, and the /paused marker. Created by this page at runtime; not shipped.
Recovery
If the displays ever look wrong: Pause (or Restore displays now) restores both panels. The watcher also restores on exit, and the supervisor restores after every watcher exit. As a last resort, disable the module in the Manager and reboot; a reboot re-initializes the panels. After a reboot you must enter your PIN before ADB works again.
